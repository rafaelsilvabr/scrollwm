# ScrollWM 0.0.1 — Developer preview

First public binary preview of ScrollWM, an experimental scrolling window manager for Windows 11 x64.

## Downloads

- **`ScrollWM-0.0.1-win-x64.zip`** — recommended portable package. Extract it and run `ScrollWM.exe`. Includes the MIT license, changelog, and usage notes.
- **`ScrollWM-0.0.1-win-x64.exe`** — the same self-contained app as a standalone executable. No .NET installation or administrator privileges are required.
- **`SHA256SUMS.txt`** — SHA-256 checksums for both downloads. In PowerShell, use `Get-FileHash .\ScrollWM-0.0.1-win-x64.exe -Algorithm SHA256` and compare with the matching entry.

The executable is unsigned; Windows may display a publisher or reputation warning. A fresh Windows installation without .NET has not been tested independently. The bundled runtime makes this package self-contained; that is not a claim that the complete compatibility matrix has passed.

## First run

1. Open the executable. Management stays off until you click **Start strip**.
2. Review the selected windows on **Scrolling strip**. Eligible open windows are selected by default. Ctrl+click to change the selection before starting.
3. Use **Ctrl+Alt+Left / Right** to focus windows, **Ctrl+Alt+W** to cycle widths, and **Ctrl+Alt+M** to transfer the focused window to the next monitor.
4. Choose **Pause & restore** to restore captured placements. **Ctrl+Alt+Shift+Esc** performs emergency restoration and releases strip shortcuts.

For a first trial, run the executable with `--fixture 5` in a separate PowerShell terminal to open disposable windows, then open the manager normally and select only those fixtures. This mode does not start the manager automatically.

## Included

- Independent horizontal strips per monitor with preserved widths.
- Keyboard navigation, reordering, and third / half / two-thirds / full width presets.
- Monitor transfer, manual additions, and opt-in automatic enrollment.
- Width-preserving edge overlap, pause/resume, and original placement/shape recovery journaling.
- Local operation without an account, telemetry, or a network service.

## Known limits and recovery

This is a developer preview, not the completed everyday MVP. Mixed display scaling, physical monitor disconnect/reconnect, full native drag/resize behavior, sleep/lock transitions, and broad application compatibility still require verification. Settings and strip order do not persist across restarts. Tray controls, automatic startup, touch/trackpad navigation, and animations are not included.

Default recovery data lives in `%LOCALAPPDATA%\ScrollWM`. If restoration remains pending after a crash, reopen the app with the same data directory and use its recovery controls. Do not delete recovery files until pending entries are resolved. Resume captures fresh original placements.

Earlier native records cover two monitors at 100% scale, 15 fixture checks, and 36 Chrome / VS Code / Xournal++ placement checks. These are results for the documented configuration, not universal application support. See the [preview guide](https://github.com/rafaelsilvabr/scrollwm/blob/v0.0.1/docs/strip-preview.md) and [compatibility matrix](https://github.com/rafaelsilvabr/scrollwm/blob/v0.0.1/docs/multi-monitor-plan.md).

## Release validation

The local Release build passed with zero warnings/errors and all 109 automated tests passed. The self-contained executable started successfully with an isolated data directory, displayed the control panel with management Off, and closed normally. ZIP contents, executable version `0.0.1.0`, and both SHA-256 checksums were verified. GitHub Actions repeats the build, tests, and packaging from the release tag before publishing its assets.
