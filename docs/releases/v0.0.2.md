# ScrollWM 0.0.2 — Developer preview

This release fixes Chrome clipping on a single monitor, reduces unnecessary redraws during window switching, and adds previously maximized windows when restored with automatic adding enabled.

## Downloads

- **`ScrollWM-0.0.2-win-x64.zip`** — portable package. Extract it and run `ScrollWM.exe`. Includes the MIT license, changelog, and these usage notes.
- **`ScrollWM-0.0.2-win-x64.exe`** — the same self-contained application as a standalone executable. No separate .NET installation or administrator privileges are required.
- **`SHA256SUMS.txt`** — SHA-256 checksums for both downloads. Use `Get-FileHash .\ScrollWM-0.0.2-win-x64.exe -Algorithm SHA256` and compare the result with its entry.

The executable is unsigned. Windows may display a warning or block it depending on its security policy and trust assessment. This release does not include an installer or automatic updates.

## Changes

- Remove temporary blanking when switching windows. Skip positioning writes and settlement delays when physical placement and clipping are unchanged. Visual Alt+Tab flicker verification remains pending.
- Reserve an 8 pixel outer margin on single monitors as well as multiple monitors, leaving room for Chrome's invisible resize border without imposing a clip Chrome rejects.
- With **Add windows automatically** enabled, windows that were maximized or minimized before Start or Resume can join when restored during the running session. Existing eligible windows left unselected remain outside the strip.
- Detect restored eligibility through location, foreground, and completed-move events as well as lifecycle events and the reconciliation fallback. Keep existing widths, capture-before-move recovery, and background focus behavior.

## First run

1. Open the executable. Management stays off until you select **Start strip**.
2. Review the selected eligible windows. Ctrl+click to change the selection.
3. Enable **Add windows automatically** before Start if newly opened or restored eligible windows should join. The option is unchecked by default and can be changed while paused.
4. Use **Ctrl+Alt+Left / Right** to navigate, **Ctrl+Alt+W** to cycle widths, and **Ctrl+Alt+M** to transfer the focused window to the next monitor.
5. Use **Pause & restore** to restore captured placements. **Ctrl+Alt+Shift+Esc** performs emergency restoration and releases strip shortcuts.

For disposable test windows, run the executable with `--fixture 5` in a separate terminal, then open the manager and select only those windows.

## Verification and limits

The Release solution builds with zero warnings/errors. All 122 automated tests pass (113 core and 9 Windows persistence tests). Native checks on one 1920 × 1200 monitor at 100% scale cover six Chrome placements, unchanged-placement writes, exact restoration, and disposable-window focus, overlap, minimize/restore, pause/resume, and fresh-process crash recovery. GUI checks cover Chrome width changes/navigation and automatic adding of a window that was maximized before Start.

Two-monitor hardware tests were not repeated for this release; earlier results remain in the compatibility record. Mixed scaling, hardware disconnect/reconnect, broader application and drag/resize behavior, sleep/lock transitions, and visual Alt+Tab flicker still need verification. Settings and strip order do not persist across restarts. A fresh Windows installation without .NET has not been tested independently.

Default recovery data stays in `%LOCALAPPDATA%\ScrollWM`. After a crash, reopen with the same data directory and resolve pending recovery before deleting files. Resume captures fresh original placements. The app has no account, telemetry, or network service.
